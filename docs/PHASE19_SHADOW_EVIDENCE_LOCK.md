## Locked engineering controls

- `ShadowEvidenceService` uses a read-only SQLite connection.
- One exact compact `evaluator_version` is required for every report.
- Missing evaluator evidence fails closed instead of returning an empty pseudo-success.
- Reporting selects aggregate columns only and does not read `proposed_text`, inbound comment text, credentials, or approved answer content.
- Reports include:
  - total evaluated;
  - first/last persisted evaluation timestamps;
  - counts by platform;
  - counts by observed route;
  - counts by Shadow outcome;
  - deterministic SHA-256 over the aggregate evidence.
- Platform, route, and outcome counts must each reconcile exactly to the selected evaluator-version total.
- `scripts/ops_shadow_report.py` exposes the same content-free report locally.
- `docs/STAGING_SHADOW_EVALUATION_PROTOCOL.md` defines dataset/evaluator identity, execution constraints, evidence fields, anomaly review, baseline comparison rules, and minimum acceptance evidence.
- No universal pass percentage or invented threshold is encoded.
